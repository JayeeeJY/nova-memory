01 · 保存

使用 macOS App

  1. 打开你已取得的 Nova Memory App，点击“开始本地使用”。首次使用会新建独立的本地记忆库。
  2. 工作台默认直接进入；点击“＋ 留住一段记忆”，粘贴选定内容并保存。
  3. 进入“AI 整理”查看原文与真实处理状态。“等待整理”表示材料已保存，还未生成结构化记忆。

App 和当前命令工程包均自带本机运行组件，无需安装 Python、Rust 或 Node。模型服务另行准备，不会因打开 App 自动下载模型或上传材料。

当前为本地工程交付：无签名包与本机 ad-hoc 签名副本分别标识。本机签名不代表 Developer ID、公证、换机兼容或公开发行。

我使用的是命令工程包或独立浏览器
  1. 在工程包中双击“启动 Nova Memory.command”。
  2. 默认无需手动解锁。若你在“设置与数据 → 打开工作台的方式”开启了凭据解锁，再双击“复制 Owner 凭据.command”并粘贴；凭据不打印到终端。
  3. 双击“检查 Nova Memory.command”查看实际地址；“停止 Nova Memory.command”仅停止这套运行器持有的服务。

双击入口适用于 macOS；其他受支持环境使用包内 bin/nova-local。消费运行同样不需要 Python。

02 · 整理

准备好后，开启自动整理

  1. 在 App 工具栏打开“运行设置”，进入“模型与检查”。
  2. 选择“本机模型”，填写你已准备的模型服务地址与模型名称。“检查模型服务”只读取目录，不发送记忆或请求生成；部分服务需要手工填写名称。
  3. 点击“保存模型并暂停整理”。保存选择会暂停处理，不会立即发送已保存材料。
  4. 切换“运行与存储”，开启“开启自动整理处理”，点击“保存并重新启动”。此后按当前模型配置处理队列中的材料。

默认可以保持“稍后配置”。调用限额为累计整理次数，不是金额或 token 预算；重启不重置次数。模型可连接也不等于提取质量已经通过。

命令工程包的整理设置

先停止服务，在工程包目录使用包内控制器设置处理开关，再重新启动：

bin/nova-local configure --bundle "/absolute/bundle" --directory "/absolute/data" --compiler on --max-calls 100

在工作台“设置与数据”保存模型名称与服务地址。远程模型需要明确材料发送范围与独立运行凭据；当前没有代管远程凭据的首用向导。这里只提供已有配置路径，不会自动选择或调用模型。

03 · 继续协作

连接同一个记忆库

  1. 进入工作台“连接”，从 AI 平台列表选择入口；系统会准备对应的接入方式，再选择使用范围。想先从 AI 保存材料，选择“采集与读取”；空库也能创建，无需勾选未来读取。
  2. 按下方对应入口添加生成的配置。本机方式通过私有文件取凭据，保持 Nova 服务运行；Owner 凭据与 Vault 主钥不要填入 AI。
  3. 在已有连接中点击“检查本机连接”，核对 Nova 协议和工具清单。通过只说明本机就绪。
  4. 在目标 AI 新会话中使用配置卡片的“开始使用的话”，再回 Nova 核对实际使用记录。没有真实调用时，不能把配置生成或本机检查当成接入成功。

默认固定当前记忆及版本；“包含未来”需明确选择。新整理内容、纠正版本不在固定范围内时，需重新选择范围。撤销连接阻止后续访问，不能收回对方已经收到的内容。

Codex · 本机 MCP

选择 Codex 创建连接，复制或下载生成的 TOML，将其中的 Nova 服务器条目合并到你使用入口的 MCP 配置，保留其他条目。支持本机 stdio 的入口使用生成的连接桥命令和参数；重新加载后在新会话验证工具。

CLI 和桌面入口分别验证；Nova 不自动编辑全局配置。具体入口是否已加载、能否完成任务，以该入口的实际结果和 Nova 使用记录为准。

Cursor · 安装与重新连接

  1. 在 Nova 配置卡片点击“在 Cursor 中添加”，在 Cursor 的安装确认中核对程序和参数。也可以展开“查看配置与手动接入”，将 Nova 的 JSON 条目合并到目标项目的 MCP 配置。
  2. 在目标项目运行命令“Cursor Settings: Tools & MCPs”，打开 Nova 连接的配置面板。若该项目来源显示 Disabled，打开对应的 Enable 开关，确认显示 Connected 和可用工具。
  3. 保持 Nova 运行，在 Cursor 新会话验证，再回 Nova 核对使用记录。任务接续时，请从 Nova 的任务卡片复制该任务的接续请求。

撤权后需要重新选择范围并创建新连接。用新配置替换项目中的旧 Nova 条目，保留其他连接。若 Cursor 仍显示旧状态，可在这条连接的配置面板点击 Reload。然后从 Nova 获取绑定新连接的接续请求。

Claude · 按实际入口配置

Claude Code 与支持本机 stdio 的 Desktop 入口，可使用生成的 JSON 中 Nova 服务器命令和参数。按该入口支持的方式合并配置，保留原有条目，重新加载后验证。

Claude 网页聊天是另一入口，不能直接使用本机进程或回环地址。当前指南不把本机配置视为网页接通，也不把 CLI 握手视为真实对话验收。

WorkBuddy · MCP 配置

复制或下载生成的 MCP JSON，在支持该连接方式的 WorkBuddy 入口添加 Nova 条目，保留原有配置。Nova 不自动写入 WorkBuddy 的配置或账号。

实际端是否接受配置、发现工具并保存/读取，需在该端验证。自动 Hook 采集单独验收，不随 MCP 配置默认启用。

ChatGPT · 安全隧道

先在本页配置卡片启动本机网关，再使用你主动提供的既有 Tunnel ID 和运行密钥，明确启动 ChatGPT 安全隧道。需要另行安装官方 tunnel-client；Nova 不自动安装、不发现旧密钥，也不创建或关联账号。

在对应 ChatGPT 入口重新加载工具，核对后实际保存或读取。网关就绪、隧道就绪与 ChatGPT 已调用分别核验。没有所需工具或凭据时，可以先使用下面的一次性上下文包。

Grok 聊天 · 临时 HTTPS 试用

目标为 grok.com 聊天；X 内嵌入口另验。本机网关启动后，可明确选择创建经 Cloudflare 转发的临时 HTTPS 入口；需要另行安装 cloudflared。

仅在 Grok 入口支持自定义 MCP 地址和 Authorization / Bearer 时，交接本次地址与临时凭据；如仅支持 OAuth，当前方案仍待适配，不改为无认证。停止后临时凭据失效，重开需更新；真实认证兼容与对话任务尚待验证。

其他 MCP 客户端

根据客户端实际支持的 stdio 或 HTTP 方式使用生成配置。远端客户端还需可达的安全连接地址及认证，不能直接使用你电脑上的回环地址。未知客户端需实际验证，不自动视为兼容。

临时任务：带走一份选定上下文

在记忆卡片点“在其他 AI 中使用这条”，自动预览该确切版本；也可从记忆库或连接页选择最多 16 条普通记忆。查看条件、时间、来源和版本后，明确复制或下载，再自行粘贴到目标 AI。

记忆更新或撤回时需重新预览；这里不会自动上传、建立连接或验证对方已使用。已带走的明文副本不能收回，也不会随之后的纠正或撤权自动更新。持续使用优先连接同一个库。

遇到问题，先看实际状态

材料一直等待整理
先确认模型选择已保存、自动整理已开启、累计调用限额未耗尽。模型未配置时保留原文等待，不需要重复保存。
显示已连接，但没有工具
在 Nova 已有连接中点“检查本机连接”，再到目标 AI 核对是否加载工具。前者检查本机协议，不能代替后者。
修改过记忆，AI 仍用旧内容
固定版本连接不会自动获得新版本。查看连接范围，必要时撤销并重新选择；一次性明文副本需要重新生成。目标 AI 已有会话内容不会被 Nova 擦除。
移动了 App 或工程包
保持数据目录原样，从当前包打开工作台，在已有有效连接中重新获取配置并更新客户端中的程序路径。Nova 不自动改写其他应用配置。
停止、重启与端口占用
App 工具栏“停止”结束对应本机服务；关闭窗口或退出 App 不等于停止。重启沿用该数据目录。端口被占用会报错，不会结束其他进程；运行设置可检查与清理已经停止的遗留状态。

记忆、备份与程序分开保管

默认数据目录：~/Library/Application Support/Nova Memory/local-workspace-v03。独立验收或自定义目录以当前运行设置为准。移动程序、停止服务或重新打开不会删除此目录；新包不自动接管旧验收库。

工作台“设置与数据”可以下载加密备份；恢复还需要另外保管的原 Vault 密钥。副本先保持隔离，不包含有效客户端授权。不要把凭据、私人库或运行日志放进公开仓库。

开发、打包与旧工程入口

以下仅用于开发环境，Python 是打包工具的依赖，不是消费运行时依赖：

python3 scripts/package-local.py --output "/absolute/new-bundle" --profile release

只打包固定运行文件，不包含数据库、密钥、来源或编译缓存。manifest 的 SHA-256 检查文件完整性，不是开发者签名。旧版 m1-local.py 与 Proposal/confirmed 路径继续保留，不代表当前自动摄入流程。

命令工程包中，遗留状态检查使用包内控制器；recover 仅清理已停止且端口空闲的状态，不删除记忆或结束其他进程：

bin/nova-local doctor --bundle "/absolute/bundle" --directory "/absolute/data"
bin/nova-local recover --bundle "/absolute/bundle" --directory "/absolute/data"
